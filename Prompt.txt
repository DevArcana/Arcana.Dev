# Arcana Personal Website — Frontend Implementation

개인 자기소개 웹사이트를 처음부터 완성도 높게 구현해줘.

이 사이트의 목적은 취업용 포트폴리오나 기업형 웹사이트가 아니라, **“Arcana라는 사람이 누구인지 보여주는 개인 홈페이지”**를 만드는 것이다.

개발, 게임, 리듬게임, 음악 등의 관심사를 자연스럽게 보여주면서도 지나치게 장난스럽거나 아마추어처럼 보이지 않는 세련된 개인 사이트를 목표로 한다.

---

# 1. 핵심 목표

사이트를 방문했을 때 다음 인상을 받을 수 있어야 한다.

* Arcana라는 닉네임이 기억에 남는다.
* 게임과 개발을 좋아하는 사람이라는 것이 바로 보인다.
* 리듬게임이라는 취미가 사이트의 개성으로 드러난다.
* 개발 프로젝트도 자연스럽게 확인할 수 있다.
* 일반적인 개발자 포트폴리오 템플릿처럼 보이지 않는다.
* 화려하지만 읽기 불편하지 않다.
* 데스크톱과 모바일 모두 완성도가 높다.

특히 흔한 AI 생성 웹사이트처럼 보이지 않게 해라.

다음과 같은 디자인을 피한다.

* 의미 없는 그라데이션 남발
* 모든 요소를 둥근 카드로 만드는 디자인
* 과도한 glassmorphism
* 무작정 네온 효과를 넣는 사이버펑크 디자인
* 개발자 사이트라고 터미널 UI를 남발하는 디자인
* 지나치게 많은 아이콘
* 모든 섹션이 똑같은 카드 그리드인 구성
* 과도한 애니메이션
* Lorem Ipsum
* 의미 없는 가짜 통계

---

# 2. 기술 스택

다음 기술을 사용한다.

* React
* TypeScript
* Vite
* Tailwind CSS
* Framer Motion
* Lucide Icons

백엔드는 사용하지 않는다.

데이터베이스도 사용하지 않는다.

사이트의 모든 데이터는 TypeScript 데이터 파일을 통해 관리한다.

가능하면 다음처럼 데이터와 UI를 분리한다.

```text
src/
├── components/
├── sections/
├── pages/
├── data/
│   ├── profile.ts
│   ├── projects.ts
│   ├── interests.ts
│   └── links.ts
├── hooks/
├── types/
├── assets/
├── App.tsx
└── main.tsx
```

컴포넌트를 지나치게 세분화하지 말고 재사용 가치가 있는 단위로 분리한다.

---

# 3. 사이트 디자인 방향

전체적으로 현대적이고 세련된 **Dark Personal Website**로 디자인한다.

단순 개발자 포트폴리오가 아니라 약간의 게임 UI 감성을 섞는다.

디자인 비율은 대략 다음 느낌이다.

* Modern Personal Website: 60%
* Game UI: 20%
* Rhythm Game / Music Identity: 20%

게임 UI 요소를 과도하게 사용하지 않는다.

전체 배경은 완전한 검정색보다는 약간 색이 들어간 매우 어두운 계열을 사용한다.

텍스트 계층 구조를 명확하게 만들고 충분한 여백을 사용한다.

페이지 곳곳에 다음과 같은 작은 디테일을 활용할 수 있다.

```text
01 / ABOUT
02 / INTERESTS
03 / PROJECTS
04 / RHYTHM
05 / CONNECT
```

섹션 번호, 얇은 선, 작은 상태 표시, 타이포그래피 등을 이용해 게임 메뉴 같은 분위기를 아주 약하게 표현한다.

# 4. Navigation

상단에 고정형 Navigation Bar를 구현한다.

왼쪽:

```text
ARCANA
```

오른쪽:

```text
About
Interests
Projects
Rhythm
Connect
```

현재 보고 있는 섹션에 따라 active navigation을 표시한다.

스크롤 시 Navbar 배경이 자연스럽게 변하도록 한다.

모바일에서는 햄버거 메뉴를 사용한다.

각 메뉴를 누르면 해당 섹션으로 부드럽게 이동한다.

# 5. Hero Section

사이트에서 가장 중요한 영역이다.

화면 높이를 충분히 활용한다.

메인 타이틀:

```text
ARCANA
```

서브 텍스트:

```text
Developer · Gamer · Rhythm Game Player
```

소개:

```text
게임을 좋아하고,
직접 만드는 것도 좋아합니다.
```

CTA:

```text
Explore
GitHub
```

단순히 텍스트를 가운데 정렬하는 Hero를 만들지 말고 비대칭적인 레이아웃과 타이포그래피를 활용한다.

ARCANA 텍스트 자체를 강력한 시각적 요소로 사용한다.

배경에는 매우 미묘한 interactive effect를 추가한다.

예:

* mouse parallax
* grid
* particles
* moving lines
* subtle noise
* rhythm pulse

단, 성능을 해칠 정도의 particle system은 만들지 않는다.

Hero 아래에는 다음 섹션으로 이동한다는 것을 알려주는 작은 Scroll Indicator를 배치한다.

# 6. About Section

섹션 번호:

```text
01 / ABOUT ME
```

내용:

```text
안녕하세요, Arcana입니다.

게임 개발과 소프트웨어 개발에 관심이 있으며,
새로운 기술을 배우고 직접 프로젝트로 만들어보는 것을 좋아합니다.

평소에는 게임을 개발하거나,
리듬게임을 플레이하고 음악을 들으며 시간을 보냅니다.
```

단순 텍스트 박스 하나로 끝내지 않는다.

한쪽에는 소개 문장을 크게 보여주고 다른 쪽에는 `PLAYER PROFILE` 형태의 작은 UI를 만든다.

예:

```text
PLAYER PROFILE

NAME        ARCANA
ROLE        DEVELOPER
INTEREST    GAME DEVELOPMENT
HOBBY       RHYTHM GAMES
STATUS      BUILDING SOMETHING
```

실제 개인정보는 최소화한다.

주소, 학교, 생년월일, 전화번호 등 민감하거나 불필요한 정보는 표시하지 않는다.

# 9. Rhythm Games Section

이 사이트에서 가장 개성 있는 영역 중 하나로 만든다.

섹션:

```text

```

```text
♪ NOW PLAYING
```

게임:

```text
maimai
SOUND VOLTEX
CHUNITHM
DJMAX RESPECT V
```

게임 이름을 큰 typography 중심으로 보여준다.

각 항목에 hover하면 작은 시각적 반응을 보여준다.

예:

* beat pulse
* moving line
* note-like element
* waveform animation

실제 게임 플레이를 구현할 필요는 없다.

게임 공식 로고나 저작권 이미지를 임의로 다운로드해서 사용하지 않는다.

텍스트 기반으로 독창적인 UI를 만든다.

장식용으로 간단한 note / lane / waveform 요소를 자체 CSS로 표현할 수 있다.

# 13. Animation

Framer Motion을 사용한다.

페이지 로드:

* Hero typography reveal
* subtitle fade
* staggered entrance

스크롤:

* section fade / slide
* project reveal
* subtle parallax

Hover:

* project image zoom
* navigation underline
* rhythm game interaction
* link movement

애니메이션은 150~500ms 정도의 자연스러운 속도를 중심으로 한다.

모든 요소가 날아다니거나 bounce하는 식의 과한 animation은 금지한다.

`prefers-reduced-motion`도 고려한다.

# 17. 데이터 구조

콘텐츠를 컴포넌트 내부에 하드코딩하지 않는다.

예:

```ts
export interface Project {
  title: string;
  slug: string;
  category: string;
  description: string;
  tech: string[];
  image?: string;
  github?: string;
  demo?: string;
}
```

프로필, 관심사, 프로젝트, 링크를 각각 데이터 파일에서 관리한다.

사이트 내용을 수정하기 위해 UI 컴포넌트를 수정할 필요가 없도록 만드는 것이 목표다.

---

# 18. 코드 품질

다음을 지켜라.

* TypeScript 타입 명확하게 정의
* any 사용 최소화
* 사용하지 않는 dependency 설치 금지
* console error가 없어야 함
* ESLint 오류가 없어야 함
* 반복되는 UI는 적절하게 component화
* 지나친 abstraction 금지
* 의미 있는 변수명 사용
* 유지보수 가능한 구조
* dead code 제거

---

# 19. 구현 방식

설명만 하지 말고 실제 프로젝트 파일을 생성하고 구현해라.

현재 저장소의 기존 파일과 설정을 먼저 확인한다.

이미 React/Vite 프로젝트가 존재한다면 기존 환경을 최대한 유지하면서 작업한다.

프로젝트가 비어 있다면 필요한 환경을 구성한다.

작업하면서 기존 코드가 있다면 무작정 삭제하지 말고 구조를 분석한 뒤 필요한 부분만 수정한다.

필요한 dependency를 설치한다.

구현이 끝나면 반드시 다음을 실행하여 검증한다.

```bash
npm run build
```

가능하다면 lint도 실행한다.

발견되는 TypeScript/build/lint 오류는 직접 수정한다.

# 20. 최종 품질 기준

최종 결과물이 단순한 튜토리얼 사이트나 AI가 자동 생성한 랜딩페이지처럼 보이면 안 된다.

특히 사이트를 열었을 때:

```text
"개발자 포트폴리오 템플릿"
```

보다는

```text
"Arcana라는 사람의 개인 공간"
```

이라는 느낌이 강해야 한다.

개발 프로젝트는 Arcana를 설명하는 요소 중 하나일 뿐 사이트 전체가 취업용 포트폴리오가 되어서는 안 된다.

리듬게임, 게임, 개발, 음악이라는 관심사를 디자인에 자연스럽게 녹인다.

하지만 게임 UI 컨셉 때문에 사용성이 떨어져서는 안 된다.

**깔끔함 → 개성 → 애니메이션 순으로 우선순위를 둔다.**

모든 구현을 완료한 뒤 전체 페이지를 다시 검토하고:

1. 디자인 일관성
2. 반응형
3. 가독성
4. 애니메이션
5. 접근성
6. 코드 구조
7. 빌드 오류
8. 불필요한 요소

를 점검해서 필요한 부분까지 직접 개선해라.
